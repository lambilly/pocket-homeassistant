# 触摸驱动：ST77922 内置 TDDI（ES3C35P）

> 采集于 2026-11-07 19:20。实现见 `components/st77922_touch/`，配置见 `pocket-homeassistant.yaml` 的 `touchscreen:` 段。
> 协议来源：LCDWIKI 官方例程 + xiaozhi-esp32 的 `lcdwiki-es3c35p` 板级移植（`main/boards/lcdwiki-es3c35p/lcdwiki-es3c35p.cc`）。
> **商家给的 spec PDF、wiki、快速开始包里都没有触摸寄存器说明**，只有引脚表。

## 为什么必须自己写

ESPHome 没有任何组件能直接驱动这颗触摸：

| 现成组件 | 为什么不能用 |
| -- | -- |
| `ft63x6`（FT6336U） | 寄存器地址 8 位、状态在 0x02、点在 0x03；ST77922 是 **16 位地址**、状态 0x0010、点 0x0014 |
| `gt911` | 协议完全不同（0x814E 状态、0x8150 点数据） |
| `xpt2046` | 电阻屏 SPI，不是电容 I2C |

所以按 ESPHome 的 `touchscreen` 基类写了一个外部组件。

## 协议（已核实）

- I2C 从机地址 **0x55**
- 寄存器地址 **16 位、大端**（先发高字节）
- 必须用 `write_read` 方式（写 2 字节地址，立刻读数据），不能分两次事务
- **不需要写任何寄存器做"清除/确认"**，全靠读操作把 FIFO 排空

| 寄存器 | 长度 | 含义 |
| -- | -- | -- |
| `0x0009` | 1 B | 最大触点数（上电读一次，决定每次要排空多少字节） |
| `0x0010` | 1 B | 状态。**bit3 (0x08) = 有触摸**，为 0 表示手指已抬起 |
| `0x0014` | 7 B × 触点数 | 触点数据，必须**一次连续读完整个 FIFO** |

单点 7 字节布局：

| 字节 | 位 | 含义 |
| -- | -- | -- |
| 0 | bit7 | 该点有效（0x80） |
| 0 | bit0~5 | X 高 6 位 |
| 1 | 8 位 | X 低 8 位 |
| 2 | bit0~5 | Y 高 6 位 |
| 3 | 8 位 | Y 低 8 位 |
| 4 | — | 压力 / 重量 |
| 5~6 | — | 保留 |

```
x = ((buf[0] & 0x3F) << 8) | buf[1]
y = ((buf[2] & 0x3F) << 8) | buf[3]
```

⚠️ 厂家也是**轮询**（约 30fps），没有可靠的中断上报方式；INT(IO47) 只作输入保留。

### 踩过的坑：只能点一次（2026-11-07）

现象：开机后点一次屏幕，圆点出现、坐标正常，然后**再也点不动**，坐标也不再更新。

根因：只读 7 字节（一个点），而控制器 FIFO 里还有剩余触点数据没被读走，
`0x0010` 的 bit3 就一直保持"有触摸"。对 ESPHome 基类来说等于手指永远没抬起：
`is_touched_` 始终为真 → 不触发 release → 触点表不清空 → 后续点击都被当成"同一次按住的移动"，
`on_touch` 不再触发。

修法：上电读 `0x0009` 得到 `max_points`，每次固定读 `7 × max_points` 字节，把 FIFO 排空。
（读满长度失败时退回 7 字节，避免整颗 IC 卡死在"永远有触摸"。）

## 引脚

| 信号 | GPIO | 说明 |
| -- | -- | -- |
| SDA | IO38 | 与 ES8311(0x18)、扩展 I2C 座共用 |
| SCL | IO39 | 同上 |
| RST | IO48 | 低电平复位，驱动上电拉低 10ms 再放高，等 100ms |
| INT | IO47 | 低有效，本驱动不用 |

## 坐标系（重要，与直觉不同）

实测（点屏幕正中 → `raw 248,142`）：**触摸原始坐标系本身就是 480×320 横屏**，
列 0~479、行 0~319，方向和屏幕显示一致。它**不是**面板原生的 320×480 竖屏，
所以既不需要 `swap_xy`，也不需要放大缩小。

配置里用 `calibration` 把原始范围标成 480×320，让映射变成 1:1：

```yaml
touchscreen:
  - platform: st77922_touch
    display: lcd
    calibration:
      x_min: 0
      x_max: 480
      y_min: 0
      y_max: 320
    transform:
      swap_xy: false
      mirror_x: false
      mirror_y: false
```

> 之前 `swap_xy: true` 的实测结果（`raw 294,78 → map 440,51`）是 raw_x×1.5 / raw_y×0.667，
> 正是"原始范围按 320×480 算、输出按 480×320 画"的结果，所以红点会偏离手指。

### 方向不对怎么调（点四个角，看屏幕上的 `raw` / `map`）

| 现象 | 改法 |
| -- | -- |
| 点左边、圆点跑右边 | `mirror_x: true` |
| 点上边、圆点跑下边 | `mirror_y: true` |
| 上下左右都反（180°） | `mirror_x: true` + `mirror_y: true` |
| 点横向、圆点往纵向跑 | 说明 raw 其实是竖屏的，改 `swap_xy: true` |

## 已知限制

1. 只上报单点（第一个有效点）；多点手势需要扩展成循环 id
2. 轮询 50ms（20fps），够点击和简单滑动；要做丝滑滚动可以降到 30ms
3. 与 ES8311 共享 I2C，等音频启用后要注意总线争用（400kHz 下读 14 字节约 0.4ms，影响很小）
4. 上电瞬间偶尔读到 (0,0)，驱动里已过滤，避免误判成左上角点击
